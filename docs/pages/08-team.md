# 用户管理 / 部门管理（Users & Departments）

> 由原「团队」页拆分为两个独立管理页，挂在侧栏「工具台」下方的「管理」序列，仅管理员可见，不固定贴底。

## 1. 页面定位

- **用户管理**：面向单个账号的只读档案 + 可编辑字段，重点是“这个人是谁、属于哪些部门”。
- **部门管理**：面向组织树的维护与人员归属，重点是“这个部门有哪些人”。
- 原「团队」页（技能/负载/项目混排）取消，资源调度能力保留在「负载与冲突」页。

两个页面和「权限管理」共同组成管理序列，顺序固定为用户管理 → 部门管理 → 权限管理。

## 2. 侧栏结构

```
┌──────────────────────┐
│ NexusFlow            │
├──────────────────────┤
│ 工作台                │
│  首页 / 收件箱 / 我的工作
│ 项目                  │
│  项目 / 负载与冲突     │
│ 资源                  │
│  资料库 / 工具台       │
│ 管理（仅管理员）       │
│  用户管理             │
│  部门管理             │
│  权限管理             │
│                      │
│                      │
├──────────────────────┤
│ 用户菜单 / 主题切换    │
└──────────────────────┘
```

- 管理序列按普通导航分组紧接「工具台」下方，不再放在第一位，也不通过自动外边距贴到侧栏底部；空白留在管理序列与底部用户菜单之间。
- 非管理员角色不渲染整个「管理」分组，直接进入 `/settings/*` 也不展示管理内容。
- 沿用系统现有黑白色阶、12.5px 列表文字、发丝边框与居中 Modal，不新增视觉主题。设计源为仓库现有 `design.pen`。

## 3. 用户管理（/settings/users）

### 3.1 用户列表

纯用户列表，字段固定为：

| 列 | 说明 |
| --- | --- |
| 用户 | 头像 + 展示名称 + `@username` |
| 所属部门 | 部门徽标；有多个部门时主部门尾缀「· 主」 |
| 角色 | 系统角色中文名 |
| 状态 | 启用 / 已停用 / 已锁定 |
| 加入时间 | 账号创建日期 |

- 顶部搜索框匹配展示名称、用户名、部门名称。
- 点击整行打开用户详情弹窗。

### 3.2 人员档案弹窗

```
+--------------------------------------------------+
| 人员档案                                      X   |
+--------------------------------------------------+
| [头像] 姓名                                     |
|        @username · 角色            [启用]         |
+--------------------------------------------------+
| 基础档案                                          |
|   姓名 [Anner          ]  工号 [A0001        ]    |
|   主组织 / 所属部门（多选，保留主部门）             |
|   创新工作室（多选，横向归属）                      |
+--------------------------------------------------+
| 等级与职责                                        |
|   管理等级 [部门主任 ▾]  专业等级 [一级工程师 ▾]   |
|   职责分类 [人员协调] [资源协调] [项目进度监督] …   |
+--------------------------------------------------+
| 技能标签（按研发/文职/需求对接分组多选）            |
+--------------------------------------------------+
| 工作状态                                          |
|   状态 [在岗 ▾]  日标准工时 [8]                   |
|   [x] 可被派发新任务                               |
+--------------------------------------------------+
| 项目归属                                          |
|   项目A  核心成员 · 负责后端 · 2026-01-01 起  [编辑][移除] |
|   添加：项目 ▾  项目身份 ▾  负责工作  起止日期  [添加]    |
+--------------------------------------------------+
|                            [取消]  [保存]         |
+--------------------------------------------------+
```

- `username` 是登录标识，不可编辑；`display_name`（姓名）可由管理员编辑。
- 主组织/所属部门为多选；创新工作室只能挂到中心或部门，单独多选。
- 管理等级（中心主任/书记 … 普通员工）与专业等级（助理/三级/二级/一级工程师）并存，仅用于展示、筛选和统计，不改变系统角色权限。
- 职责分类从固定职责字典多选：人员协调、资源协调、项目进度监督、技术选型与路线、技术框架收集与培训、内部工作协调、成员执行。
- 技能标签按研发类、文职类、需求对接类分组多选；已有自定义标签保留并继续可取消。
- 工作状态为人员状态（在岗/出差/培训/休假/不可用/离职），与账号状态（启用/停用/锁定）分开；日标准工时用于负载计算，离职或不可用不再派发。
- 项目归属维护项目身份、负责工作、加入/退出日期；成员关系仍以项目 `member_ids` 为准，身份明细写入项目 `members` 映射，移出时保留结束日期。
- 未改动时保存按钮禁用，保存成功后刷新列表并关闭弹窗；项目归属的增删改即时生效。

## 4. 部门管理（/settings/departments）

### 4.1 布局

```
+-----------------------------------------------------------+
| 部门管理                        [+ 新建部门]                |
+----------------------+------------------------------------+
| 部门结构              | 智能技术中心  [中心]  12 人         |
|  CNPC                |   [添加成员] [编辑] [子部门] [删除] |
|    研究院      2      +------------------------------------+
|      智能技术中心 12  | 成员            角色      账号状态   |
|        研发部   3     | [头] 张伟       部门主任   启用     |
|        项目部   5     | [头] 李文静     技术总监   启用     |
|      创新工作室 0     | ...                                |
+----------------------+------------------------------------+
```

- 左侧：部门树，无限层级，默认全部展开，可逐级收起。
- 节点 hover 显示「新建子部门 / 编辑 / 删除」三个图标。
- 节点右侧显示该部门直属成员数。
- 右侧：选中部门的成员列表，支持添加成员、移出成员。

### 4.2 部门维护

- 新建部门：名称、类型（公司 / 二级单位 / 中心 / 部门 / 工作室）、上级部门。
- 组织层级固定为公司 > 二级单位 > 中心 > 部门；创新工作室只能挂在中心或部门下；根节点只能是公司。后端在新建和移动时校验，非法层级直接拒绝。
- 编辑部门：名称、类型、上级部门；不能移动到自己或自己的下级，后端拒绝环形结构。
- 新建、删除及调整上级仅限系统管理员 / 中心主任；部门管理员仍受既有组织范围约束。
- 删除部门：确认后调用删除接口；若仍有子部门、人员、项目或任务关联，后端返回 409，页面提示无法删除。
- 部门名称即页面展示名称，不引入编码等冗余字段。

### 4.3 人员归属

- 一个人可以属于多个部门；保留原主部门，移除原主部门后才取剩余部门中的第一个。
- 只修改展示名称时必须保留所有部门；只修改部门时必须保留展示名称。未知字段、修改用户名和错误类型直接拒绝。
- 编辑表单携带 `updated_at` 防止覆盖别人已保存的修改；批量加人部分失败时立即刷新已成功结果，不谎报全量成功。
- 添加成员：弹窗内搜索并多选当前不在该部门的用户，确认后逐人追加部门。
- 移出成员：从该用户的部门列表中移除当前部门，其他部门归属不受影响。
- 主部门保持稳定：编辑时若原主部门仍在列表中则不变，否则取列表第一个。

## 5. 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/admin/users` | 用户列表，含 `org_id` / `org_ids` 及人员档案字段 |
| PATCH | `/api/admin/users/:id/profile` | 修改姓名、部门、工号、等级、职责、技能、工作室、工作状态、工时、可派发 |
| GET | `/api/admin/users/:id/projects` | 人员项目归属（含身份、负责工作、起止） |
| PUT | `/api/admin/users/:id/projects/:projectId` | 新增/更新项目归属，同步项目 `member_ids` |
| DELETE | `/api/admin/users/:id/projects/:projectId` | 移出项目，保留结束日期与历史身份 |
| GET | `/api/orgs/tree` | 部门树 |
| POST | `/api/orgs` | 新建部门（校验层级） |
| PATCH | `/api/orgs/:id` | 改名 / 改类型 / 调整上级（校验层级与环） |
| DELETE | `/api/orgs/:id` | 删除空部门 |

- 管理页及用户管理、部门写接口要求管理员身份并受 `people:manage` / `org:manage` 功能权限约束；既有部门树读取继续供业务功能复用，不因此扩大写权限。
- 展示名称、部门归属及人员档案字段变更写入审计日志（`admin.user_profile`）；项目归属写入 `admin.user_project` / `admin.user_project_remove`。
- CLI：`nexusflow admin users`、`nexusflow admin user-profile <id> '<json>'`、`nexusflow admin user-project <user-id> <project-id> --role core --responsibility "后端"`、`nexusflow admin user-project-remove <user-id> <project-id>`、`nexusflow orgs tree`、`nexusflow orgs create|update|delete`。
- 结构调整复用 CLI：`nexusflow orgs update <id> '{"parent_id":"上级ID"}'`；改为根部门传 `null`。
- 服务器验收：`python3 /opt/nexusflow/validation/<当前提交>/source/scripts/verify-admin-management.py --write-test`。仅新建随机前缀验收账号/部门；结束时停用并精确清除本轮夹具，不改现有用户与业务数据，保留审计。

## 6. 权限与异常

- 普通成员看不到管理序列，直接访问接口返回 403。
- 列表加载失败时保留页面框架并提示错误，不能把失败显示成「暂无部门 / 暂无人员」。
- 部门树为空时提示「暂无部门」，并提供新建入口。
- 保存失败使用全局 toast 展示后端错误，不关闭弹窗。
