3. 后端领域（API 全部 /api 前缀）
---------------------------------
数据模型与功能以 docs/origin-prd.md + docs/00-overview/domain-model.md 为准，至少覆盖：
- auth：本地登录（bcryptjs + jose 会话 cookie）+ Portal ticket（见 §4）+ /healthz /readyz
- org：公司/二级/三级单位/部门/创新工作室 树；人员（职称等级、技能标签、项目身份）
- projects / tasks：任务类型（科研·公司级/处级/中心级、市场、出差、文职、党建、学习、休假）、
  负责人/成员分工/每日投入/起止时间/概述版本留痕、资料关联
- dispatch：标准流程 + 后补流程（发起人确认）；跨部门派发需授权；审批流（部门主任→中心主任）
- schedule/load：按人按日负载计算（每日投入 vs 可用 8h），全天任务锁定（置灰），冲突检测与报警
- files：MinIO 上传下载，属性分类（个人报告/整体报告/汇报PPT/申报报告/数据集/会议纪要）
- inbox：审批/指派/@提及/冲突预警/系统通知
- home：今日焦点/统计带/7日时间线/风险雷达/团队负载热力图 的聚合接口
- tools：工具台条目（静态注册表即可，AI 工具只做入口跳转占位）
- reports / config / admin：按 docs/pages 中 12-reports、14-settings、15-admin 的最小可用实现
- seed：内置演示数据脚本，内容与设计图一致（智慧油田数据平台、张伟/陈思远/李文静/王强/赵敏/刘洋/孙倩/周杰/吴迪/王建国 等）
PostgreSQL 为主存储（schema=nexusflow 或用 search_path），Redis 做会话/缓存，MinIO 存文件。
服务端鉴权：按角色裁剪（中心主任全量 / 副主任分管 / 部门主任本部门 / 负责人本项目 / 成员个人+本项目）。

4. Portal SSO（与 Northline/Documind 完全一致）
----------------------------------------------
环境变量同名：PORTAL_MANAGED / PORTAL_AUTH_ENABLED / AUTH_LOGIN_MODE(local|portal) /
PORTAL_BASE_URL / PORTAL_EXCHANGE_ENDPOINT（默认 /api/auth/exchange-ticket）。
流程：
  Portal 前端跳转 -> GET  /auth/portal/callback?code=<id>:<secret>
  后端 POST {PORTAL_BASE_URL}{PORTAL_EXCHANGE_ENDPOINT}
    body: { system_code: "nexusflow", code }
  返回: { user_id, username, display_name, email, tenant_id, tenant_code, tenant_name,
          system_code, portal_roles: ["user"|"tenant_admin"|"tenant_owner"],
          system_roles, permissions: string[], expires_at }
  -> 本地按 username 建/更新用户 -> 发本地会话 -> 302 到 /
portal role 映射：tenant_owner/tenant_admin -> 中心主任权限；user -> 项目成员。
（Portal 服务端 systems 表新增 nexusflow 由协调者负责，worker 不动 Portal 仓库。）

流程（照 Northline/scripts/）：
  make deploy-build  = 本地 web 静态导出 + bun build --compile --target=bun-linux-x64

本地不做任何服务启动/测试（项目铁律），本地只写码 + typecheck + 单测。
